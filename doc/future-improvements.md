# Future Improvements（后续功能改进）

记录尚未实现的功能改进计划。目前有三个主题：让流场寻路在大地图上也能低成本运行
（局部刷新）、多玩家时的流场组织方式，以及射击/武器/击退与原版的差异（待修）。

---

## 流场：大图下的局部刷新方案

### 动机

`MapData.computeFields()` 每次刷新都会重算整张图的距离场 + 方向场（每 60 物理帧一次，
`flowDirty` 置位时还会立刻加算一次）。当前房间尺寸的地图没问题，但成本随格子数线性增长，
而且两个实现细节让情况更糟：

1. **字符串键字典**。格子以 `"%s-%s" % [x, y]` 作 key，每格一次字符串拼接 + 哈希，
   是大图下的主要开销。
2. **局部事件触发全局重算**。放/碎一个油桶或假墙只影响该格周围一小块区域，
   却把整张图重算了一遍。

下面的方案按性价比排序。第 1、2 步改动小、足以覆盖 Boxhead 的场景（房间制地图、障碍增删
很少、玩家 1~2 个）；第 3、4 步是更大规模地图的保险。

### 第 1 步 —— 字典换扁平数组（不改算法）

- 距离场改用 `PackedInt32Array`，下标 = `y * width + x`。
- 方向场改用 `PackedByteArray`，每格只存 0~8 的方向编号，不再存 `Vector2`。
- 障碍表可照旧（本来就按键查），或者在 BFS 里再镜像一份 `PackedByteArray` 位图，让"是否障碍"
  的判断变成 O(1)。

只此一步就能去掉主要常数开销，后面所有方案都受益。

### 第 2 步 —— 降低重算频率（不改算法）

流场的源点是玩家所在格，而玩家相对格子的移动速度很慢。流场滞后玩家 0.3~0.5 秒完全无感
——僵尸追的只是一个"慢半拍、偏一两格的影子"。

- 按定时器重算（例如每 0.5 秒），或者玩家跨满 N 格才重算。
- 障碍增删仍可走 `flowDirty` 立即重算，等第 3 步落地后再改走增量更新。

### 第 3 步 —— 障碍增删走增量 BFS（真正的局部刷新）

障碍增删是局部事件，只有"最短路径曾经过该格"的格子距离会变化。利用 BFS 距离的两个单调性：

- **删障碍（距离只会变小）**：以刚释放的格为新源做一次 BFS，只扩展"新距离 < 已记录距离"的格，
  否则剪枝。只重写距离真正变化了的格子的方向。
- **加障碍（距离只会变大）**：做"升距传播"——从被堵格那些 `dist == d+1` 的邻居出发，
  检查它们除被堵格外是否还有等距的替代父格；没有就把距离 +1 并继续向上游传播，
  有则停止。受影响区域恰好就是所有路径曾经过这格的范围，其余格子一个字节都不用动。
- 可选：每物理帧限制处理的格子数（时间切片）。实际上障碍增删很少见（玩家放油桶、
  墙被打碎），一次更新一两帧内就跑完。

### 第 4 步 —— 大图分层：远场粗场 + 近场窗口

如果地图大到几万格，连数组化的全量 BFS 都不能接受时，再上分层：

- **粗场**：把 16×16 格合成一个 chunk，在 chunk 粒度跑 BFS（几百个节点，成本可忽略），
  供远处僵尸定向。
- **近场窗口**：只维护玩家周围半径 R（例如 48 格）内的细粒度流场。BFS 以玩家为源，
  队列里弹出的格距离超过 R 就不再扩展——成本从 O(全图) 降到 O(R²)。
- 窗口随玩家移动而平移。窗口外的僵尸走粗场（朝玩家所在 chunk 走），进入窗口后再切细场。

### 落地顺序建议

1. 第 1 步（数组化）——改动小，收益立竿见影；
2. 第 2 步（拉长重算间隔）——几行代码的事；
3. 第 3 步（增量更新）——只有障碍频繁增删出现卡顿时才需要；
4. 第 4 步（分层）——只有单次全量 BFS 真正不可接受时才上。

对 Boxhead 的房间制玩法，第 1 + 2 步基本够用，第 3 步是廉价保险，第 4 步大概率用不上。

## 流场：多玩家时的组织方式

### 现状

`MapData.flowFieldDict` 以 `playerId` 为键，**每个玩家一张完整流场**；
`map.gd updateFlowField()` 对每个玩家各跑一次全量 BFS，僵尸用 `z.targetId()`
查自己目标那张场。玩家数 P = 1 时没有问题，但成本随 P 线性放大，而且和上面的
优化方案叠加时会漏乘 P：

- 第 1 步数组化：省的是常数，但仍是 P 张场；
- 第 2 步降低频率：P 个源点各自的场都要按自己的节奏刷；
- 第 3 步增量更新：一处障碍增删要对 **P 张场各做一次**升距/降距传播；
- 第 4 步近场窗口：玩家分散时得维护 P 个窗口，成本回到 ×P。

### 方案 A：多源叠加场，一张"指向最近玩家"的场（推荐）

单次 BFS 以**所有存活玩家为源**（多源 BFS，距离取最近），整张图只存一张场，
方向指向"路径最短的玩家"。

- **语义与现有逻辑天然一致**：`Zombie.findTarget()` 本来就是选最近的玩家，
  多源场恰好就是"去最近玩家"的全图梯度，僵尸群会自动分流到不同玩家。
- **成本与玩家数无关**：第 1~4 步的优化都只作用于一张场——障碍增量只传播一次；
  窗口化时对每个玩家各开一个窗口（多源 BFS 的源就是各窗口，天然支持玩家分散）。
- **玩家死亡/复活** = 增删一个源，正好复用第 3 步的增量传播（删源做升距、
  加源做降距）。全灭时场清空、僵尸站桩，现有逻辑已经这么处理。
- **代价**：僵尸已承诺的目标可能和场指向的"最近玩家"不一致——两个玩家距离
  差不多时，僵尸会在中途漂移切换目标。要么接受（把 `refreshTarget` 的语义改成
  "场指谁追谁"，对僵尸海游戏通常没问题），要么用方案 B。

### 方案 B：保留每玩家一张场（现状结构的优化版）

维持 `flowFieldDict` 不变，第 1 步数组化、第 2 步降频、第 3 步增量传播
**对每张场各执行一次**。障碍增删的传播区域通常很小，P = 2 时完全可以接受。

适用场景：必须保证每只僵尸**严格追自己锁定的目标**——比如恶魔有固定仇恨、
或者以后要做"拉怪 / 仇恨转移"类玩法。缺点：玩家一多，第 3、4 步的成本都是 ×P。

### 建议

- Boxhead 的僵尸本来就是"追最近玩家"，直接用**方案 A**：一张多源场替换
  `flowFieldDict`，顺手删掉 `z.targetId()` 的分支，所有大图优化只对一张场生效。
- 如果将来出现"僵尸必须锁定目标"的玩法，再退回方案 B——届时增量传播按场
  执行即可，两份方案不冲突。

## 射击、武器与击退：与原版的差异（待修）

下文原版行号均指 `F:\scripts\__Packages\...`，重制行号指本仓库
`box-head-remake/...` 下的文件。

### 结论

武器面板（伤害、射速、射程、弹药）基本一致，除霰弹枪外，单发伤害的 TTK 也一致。
差异几乎都发生在**命中之后**：

- **原版**：子弹瞬时命中 → 把 Affect 压进目标列表 → 目标下一次 `ProcessAffects()`
  才扣血 → 按伤害和质量推导击退 → 由击退距离反推硬直帧数。
- **重制**：射线命中的同一帧直接 `hit()` 扣血 → 武器写死的 `hitFeedback`
  （px/s）覆盖伤害/质量公式 → 固定的 `hurtDelay` 控制硬直。

结果：同一把枪对僵尸/恶魔的推动距离、僵直时间和死亡演出与原版不一致；恶魔质量
从 5 改成 1 又把偏差放大成"部分武器推得更远、部分更弱"。此外霰弹枪弹丸、火球撞墙、
玩家受击公式还有各自独立的行为差异。

### 命中与受伤链路

原版：

1. 子弹生成后的第一个逻辑 tick 就做 `Collide_Line` 瞬时命中
   （`CThing_Shot_Bullet.as:45-58`），画面上只有一条持续 2 tick 的曳光（`:28`）。
2. 命中不直接扣血，而是把 `CThing_Affect_Bullet` 压入目标的 `mAffectors`
   （`:58`）；目标下一次 `ProcessAffects()` 才结算（`CThing_Creature.as:442-497`）。
3. `CMap_Affect.as:41` 先按 `mAffectFlags` 过滤免疫，再用
   `mAffector.mID != mID` 排除攻击者自己（近战僵尸不会打到自己；爆炸排除的是
   爆炸特效自己，不是发射者）。
4. 致命伤不会立即死亡：先进入 `State_BulletHit`，照常位移、衰减、流血；
   `mLife <= 0` 只标 DEAD（`CThing_Creature.as:336-340`），状态结束才
   `CheckForDead()` → `State_Dying`（`:341-352`、`:388-395`）。

重制：

1. 射线命中的同一帧直接 `owner.hit(damage, result.position, hitFeedback)`
   （`script/weapon/hand_gun.gd:91`、`uzi.gd:89`、`shotgun.gd:109`、
   `railgun.gd:84`）。
2. `hit()` 立即扣血（`script/character/zombie.gd:616`、`devil.gd:311`）；
   `hp <= 0` 直接 `die()` 并 return（`zombie.gd:618-620`、`devil.gd:312-314`），
   没有任何击退或硬直。
3. 结果：面板伤害相同的武器 TTK 一样，但"死亡演出"不同——原版是
   "被打飞 → 硬直 → 倒下"，重制版是"直接进入死亡状态"。

### 原版击退模型

| 来源 | 击退初速（格/tick） | 出处 |
| --- | --- | --- |
| 子弹 / 火球 | `max(dmg × 2/5 / 32, 0.3) / mass` | `CThing_Creature.as:489` |
| 爆炸 | `min(dmg × 2/5 / 32 / mass, 0.3)` | `CThing_Creature.as:471` |
| 僵尸近战 | `max(dmg / 5 / 32 / mass, 0.3)` | `CThing_Creature.as:480` |

- 位移每 tick ×0.65（`CThing_Creature.as:331`），逻辑帧率 25 tick/s；
  总位移 = 初速 / 0.35 ≈ 2.86 × 初速。
- 方向 = `targetPos − affector.position`，连续向量，不量化
  （`:471`、`:480`、`:489`）。子弹的 affector 是还在枪口的子弹对象
  （`CThing_Shot_Bullet.as:58`），所以方向≈枪口 → 目标。
- 硬直帧数不是按伤害算，而是由击退初速反推（`State_BulletHit_Init`，
  `CThing_Creature.as:299-307`）：威力越大硬直越长；硬直结束再 Sleep 3 tick
  （`:341-350`）。
- 质量：生物基础 1（`CThing_Creature.as:49`），玩家 2
  （`CThing_Creature_Player.as:146`），**恶魔 5**（`CThing_Creature_Devil.as:89`）。

### 重制击退模型

- `knockbackSpeed()` 公式其实照抄了原版（`zombie.gd:740-749`、
  `devil.gd:330-337`），但只有 `recoil == 0` 时才走它
  （`zombie.gd:638`、`devil.gd:325`）。
- 枪械传入的是正数 `hitFeedback`（`script/weapon/weapon.gd:31`）：
  手枪 100、UZI 50、霰弹 200、轨道炮 50 px/s。正数直接当击退初速，
  **跳过伤害公式和质量**；伤害升级（Double/Quad）只改 damage，不改
  `hitFeedback`（`mapData.gd:513-572`、`player.gd:209-218`），所以原版枪械
  "伤害越高推得越远"在重制版里不存在（爆炸仍走伤害公式，但有 0.3 格/tick 上限）。
- 视觉/位移上，60Hz 的 Hurt 状态每个物理帧移动完整 `knockbackDelta`
  再 ×0.65（`zombie_states/zombie_hurt.gd:29-40`）。在初速相同的前提下，
  总距离与原版一致（同样的几何级数和），但 n 帧只需 n/60 秒，原版是
  n/25 秒——**同样的距离被压缩到 0.4 倍时间里**，看起来又快又短。
- 硬直固定：僵尸 0.5s（`zombie.gd:94`）、恶魔 0.4s（`devil.gd:37`），
  与武器和伤害无关。

### 逐项偏差与修复顺序

1. **让击退回到"伤害 × 质量"（最高优先级）**
   - 枪械不再传正数 `hitFeedback`，改传 0，让 `knockbackSpeed()` 生效；
     或者把 `hitFeedback` 改成倍率而不是绝对速度。
   - 这样 Double/Quad 伤害升级会自动放大击退，与原版一致。
   - 完成后恶魔质量改回 5（`devil.gd:41` → `5.0`），否则质量仍然不参与
     枪械击退。按上表，修复后应回到"手枪 30/6、UZI 40/8、霰弹 58/12、
     轨道炮 114/23"。

2. **霰弹枪（高优先级）**
   - 原版基础是 3 发：中心 0°、左右各 1.25°
     （`CThing_Weapon_Shotgun.as:57-67`）；WideShot 1/2 级各加一对，
     变成 ±2.5°/±5° 或 ±3.75°/±7.5°，总数都是 5 发
     （`CUpgrades.as:248-252`）。三发都能命中同一个目标，
     贴脸总伤害 51 × 3 = 153，一枪能秒 100hp 的僵尸。
   - 重制是 4 发、`-15° / -7.5° / 0° / +7.5°` 再各加 ±2° 随机
     （`shotgun.gd:78-81`），而且所有弹丸共用 `excludeObj`
     （`:99-110`）——同一目标一枪最多吃 1 发 51 伤害，贴脸也要两枪。
     扇形还缺了 +15°，整体偏左。
   - 对 1000hp 的恶魔差距更明显：原版贴脸 7 枪，重制要 20 枪；
     Double/Quad 伤害升级会把这条差距继续放大。
   - 修复：恢复 3 发对称弹丸；每发弹丸独立的命中记录（但同一发在
     2 个检测帧内仍不能重复命中）；升级改成加弹丸/加角度，不要只改
     `splitAngle`。顺手修正 `mapData.gd:555` 的错误注释——原版
     `Fire()` 确实读取 `mWideShot`，"升级无效"的说法不成立。

3. **致命伤也走击退/硬直（中高优先级）**
   - 原版致命伤仍会完整进入 `State_BulletHit`，击退、流血、硬直，
     状态结束才死亡（`CThing_Creature.as:336-352`、`:388-395`）。
   - 重制在 `hp <= 0` 时立即 `die()`（`zombie.gd:618-620`、
     `devil.gd:312-314`）。要还原"被打飞再倒下"，需要给目标加一个
     `pendingDeath` 标记：仍进入 Hurt，等击退和 `hurtDelay` 结束再 die；
     注意 Chase 的退出条件不能把它提前拉回去。

4. **击退方向（中优先级）**
   - 原版是连续向量（`CThing_Creature.as:471/480/489`），子弹从枪口算
     （`CThing_Shot_Bullet.as:58`）。
   - 重制把射线的 `result.position`（命中点）当攻击点
     （`hand_gun.gd:91`、`uzi.gd:89`、`shotgun.gd:109`），再经
     `angleFromVector()` → `vectorFromAngle()` 量化到 8 方向
     （`zombie.gd:639-644`）。掠射时"命中点 → 圆心"可能接近法线，
     不是弹道方向；8 方向量化又引入最多 22.5° 误差。
   - 修复：武器把枪口/射线起点作为攻击来源传给 `hit()`；`hit()` 里直接
     用 `(global_position - attackPos).normalized()`，不再量化。
     顺手改正 `zombie.gd:639-640` 中"原版取 8 方向 mAngle"的错误注释。

5. **击退衰减的时间基准（中优先级）**
   - 原版每 1/25 秒应用一次位移并 ×0.65（`CThing_Creature.as:331`）；
     重制每 1/60 秒应用一次（`zombie_hurt.gd:29-40`）。总距离相同，
     但耗时只有 0.4 倍，而且物理帧率一变表现就变。
   - 修复：在 Hurt 状态里做 25Hz 累积器——`acc += delta`，每满 1/25 秒
     应用一次完整位移并 ×0.65；或者用 `pow(0.65, delta * 25)` 做帧率
     无关衰减。注意**只改衰减、不改位移**会让总距离变短，两处要一起改。
   - 固定 `hurtDelay` 0.5s 已经接近原版的 0.48~0.64s 区间；做完击退
     距离和 25Hz 位移后，硬直没必要再严格按初速反推。

6. **火球（中优先级）**
   - 原版火球撞静态墙会原地爆炸（`CThing_Shot_FireBall.as:55-60` →
     `GenericCollide` → `Collide_Map`），命中角色走 FireBall 的默认
     Affect 分支，有击退（`CThing_Creature.as:487-493`）。
   - 重制 `fireball.tscn:81-82` 的 mask = 52，不含 staticWall(8)；
     `fireball.gd:91-109` 只用 `get_overlapping_areas()`，所以穿过静态墙。
     命中角色时 `recoil = -1`，僵尸/恶魔完全不推；玩家侧又没处理负数。
   - 修复：火球飞行时对静态墙做格子/射线检测并立即爆炸；命中角色改传 0，
     让它走伤害公式；玩家的 `hit()` 补上 `recoil < 0` 分支，或者改成
     "伤害来源枚举"而不是用负数当哨兵值。

7. **玩家受击公式与爆炸击退（中优先级）**
   - 原版玩家质量 2，子弹/火球/近战/爆炸都会推（见上表）。重制的
     `player.hit()` 只有 `velocity = attacker * recoil`，爆炸传 0 →
     无击退；僵尸近战传 20px/s → 约 3px（原版 ~27px）。
   - 修复：给玩家加与僵尸一致的 `knockbackSpeed()` 分支（爆炸用 min，
     子弹/火球用 max，近战用 `max(dmg/5/32/mass, 0.3)`），并让爆炸/
     近战传"来源类型"而不是随手写 recoil。玩家的 Hurt 位移也建议改成
     同一套 25Hz 模型，否则距离对了时间还是不对。
   - 注意：玩家现在的手枪/霰弹击退（~14/28px）碰巧接近原版（~15/29px），
     改公式后不要用旧的 `lerp` 模型，否则会推过头。

8. **其他小项（低优先级）**
   - **火箭速度**：原版 0.5 格/tick 起步、每 tick ×1.1
     （`CThing_Shot_Rocket.as:40`、`:52`），重制恒定 700px/s

   - **轨道炮穿静态墙**：重制 ray 的 mask = 52，不含 staticWall

   - **玩家无敌时长**：原版出生 200 tick = 8s

   - **`friendlyFire` 设置未接线**：设置面板和存档都会写
     （`settings.gd:158`、`ui/game_setting_panel.gd:153-154`），但玩法
     代码没有读取。这不是原版差异（原版源码没有这个开关），是重制版
     自己的死配置——要么接线，要么删掉。

### 不是差异，不要误修

- **爆炸自伤**：原版 `CMap_Affect.as:41` 的 `mAffector.mID != mID`
  排除的是 affector 自己（爆炸特效/子弹/近战攻击者），不是 `mOwner`；
  `CThing_Affect.mOwner` 在源码里从未被读取。玩家仍会被自己的火箭/油桶
  炸到。重制版爆炸 mask 包含 playerBody，行为一致，不需要加"排除发射者"。
- **武器面板、血量**：26/35/51/100/250、僵尸 100、恶魔 1000、玩家 200
  都与原版一致；要调的是击退和命中逻辑，不要重复改数值。
- **僵尸/恶魔的爆炸击退**：~27px 与原版一致（`explosion.gd:107`、
  `zombie.gd:743-744`），只需要修玩家侧的爆炸击退。
- **爆炸半径与衰减**：`2 + max(dmg − 100, 0) × 0.005` 格、三档 100/75/50%
  与原版一致（`CThing_Effect_Explosion.as:26`、
  `CThing_Affect_Explosion.as:14-26`），不要动。
